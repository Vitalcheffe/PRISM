## 6. Gap-3 verification: layer-0 weights carry signal

**Method.** For two input vectors (baseline and +25%-of-range perturbed), compute the
network's output, then zero all layer-0 weights, recompute, and measure the delta.
If layer-0 weights carry signal, the perturbed delta should be non-trivial.
(The baseline delta is expected to be ~0 because at baseline, all normalized inputs are 0,
so layer-0 weights never activate — this is by design of the normalization, not a bug.)

### 6.1 With Gap-3 fix (layer-0 LR 3×, biasDecay 0.001)

| Metric | Value |
|---|---:|
| Layer-0 weight count (nonzero out of 1504) | 1504 |
| Layer-0 weight mean | 0.052501 |
| Layer-0 weight std | 0.251694 |
| Layer-0 weight max abs | 1.224067 |
| Perturbed max output delta (after zeroing layer 0) | 3.2770e+4 |
| Baseline max output delta (after zeroing layer 0) | 0.0000e+0 |
| **weightsMatter** (perturbedMaxDelta > 1e-3) | **true** |

### 6.3 Interpretation

- The fix increased layer-0 weight std by **+0.0376**
  (from 0.2141 → 0.2517).
- The fix increased layer-0 weight max abs by **+0.3688**
  (from 0.8552 → 1.2241).
- Zeroing layer-0 weights at a perturbed input changed the output by
  3.28e+4 (with fix) vs 1.27e+4 (without).
- **Verdict**: ✓ layer-0 weights carry signal (weightsMatter = true).

> **Note on the baseline delta being 0.** The network's input normalization
> subtracts `lever.baseline` from each input. At baseline, all normalized inputs are
> exactly 0, so the layer-0 weighted sum is 0 (since `0 × w = 0`), regardless of
> what the weights are. The output at baseline is determined entirely by the
> biases of all three layers. This is why we verify at a *perturbed* input —
> zeroing layer-0 weights only changes the output when the inputs are non-zero
> in normalized space. The biasDecay term addresses the *training dynamics*: it
> prevents biases from growing unboundedly to compensate for small layer-0 weights,
> forcing the network to encode signal in the weights themselves.

## 7. Honest interpretation

- On raw MAE, formulas beat the NN on 0/6 indicators; the NN beats formulas on 6/6.
- On directional accuracy, formulas get 53.6% vs NN at 92.9% of year-over-year change directions correct.
- The NN was fine-tuned on these EXACT 6 data points (in-sample), so its MAE on them is artificially low — this is a fit-quality diagnostic, NOT a generalization test. The directional accuracy is the more honest signal: it tests whether the network learned the *shape* of the historical trajectory, not just memorized the 6 target values.
- The Gap-3 fix is verified: zeroing layer-0 weights changes the output by 3.28e+4 (well above the 1e-3 threshold).

### 7.1 What this backtest does NOT prove

1. **No out-of-sample test.** The NN trained on these exact 6 years and is evaluated on the same 6. A proper generalization test would hold out, say, 2010 and 2015, train on the other 4, and predict the held-out years. With only 6 data points, this is statistically weak — but the framework is in place to add more years as data is collected.
2. **Lever values are PROXIES, not authoritative.** The 47 levers per year are reconstructed from published sources where possible (interest rate, minimum_wage, public_investment) and estimated otherwise (doctors_per_1k in 2000 ≈ 0.4 is an educated guess from WHO trend data). Errors in lever reconstruction propagate to BOTH the formula and NN predictors, so the comparison is fair but the absolute MAEs are upper bounds on the *model's* error.
3. **The formula predictor is fed prevGdp + accumulatedDebt directly from the historical record.** This is a 'cheat' — in production, the engine computes these from its own state. The backtest measures the *formula's* fidelity to the data when given the right macro state, not the engine's ability to track the trajectory over multi-year simulation.
4. **The 6 indicators were chosen because they have clean, published, year-by-year data.** Indicators like `stability`, `revolution_risk`, `gini`, `poverty_rate` are harder to backtest (sparse or model-dependent definitions).

## 8. Reproducibility

```bash
cd mini-services/simulation-engine
bun run validation/backtest.ts
```

The harness is deterministic EXCEPT for the NN's `pretrainFromFormulas` step, which
uses `Math.random()` to generate the 200 synthetic samples. To make runs comparable,
the `preTrainOnRealData` step uses fixed real data (no randomness), so the fine-tuning
trajectory is deterministic given the same starting network. For full reproducibility,
call `Math.seedrandom(...)` before `createNetwork()` (not done here to avoid adding a
dependency).
